Key Findings

The portfolio has a strong technical baseline — HTTPS via Vercel, a valid robots.txt, a well-formed sitemap with priorities and lastmod dates, canonical tags on all three pages, and complete Open Graph and Twitter Card tags site-wide. The most critical gap is structured data: only the homepage has a JSON-LD schema — the about and projects pages have none, leaving Google without machine-readable context on those pages. The about page H1 is injected via JavaScript, which means crawlers see an empty <h1></h1> in the raw HTML. Additionally, all four project cards link to the same GitHub profile URL rather than individual repos, which signals thin content and misses keyword-rich anchor text opportunities. Two title tags and two meta descriptions exceed Google's recommended character limits.

Top 3 Priorities
Highest-impact actions to take right now
1
Fix the JS-injected H1 on about.html
The about page's H1 is empty in raw HTML — the text is written into it via JavaScript. Add static fallback text inside the <h1> tag (e.g. "About Sumeet Kobarne — Full Stack Developer") so Google sees it on the first crawl, before any JS executes.
Expected impact: Ensures about.html has a crawlable H1, improving keyword signal for branded searches landing on that page.

about.html needs a Person schema (same as index.html). projects.html needs an ItemList schema listing each project as a CreativeWork. This gives Google rich context and enables rich result eligibility for all three pages.
Expected impact: Unlocks rich results, improves how Google understands the pages, and boosts click-through rate in SERPs.
Critical
3
Link each project card to its individual GitHub repo
All four project cards currently link to https://github.com/sumeetdk16 — the profile, not the specific repo. Replace each "Learn more ↗" link with the actual repo URL (e.g. github.com/sumeetdk16/waste-snap). This also means the anchor text can be more descriptive ("View Waste Snap on GitHub").
Expected impact: Removes thin-content signal, adds keyword-rich anchor text, and makes the projects page more useful to both crawlers and users.

Add an H2 above the project grid: <h2>Featured Projects</h2> or category H2s like "Web Applications" and "Tools". The existing project name H3s can stay as-is.

Security & Server Headers

HTTPS enforced via Vercel

Vercel automatically provisions and renews TLS certificates. All traffic is served over HTTPS. HSTS is enabled by Vercel's edge network by default.

Pass

No custom security headers configured

Without a vercel.json headers config, Vercel does not add CSP, X-Content-Type-Options, X-Frame-Options, or Referrer-Policy headers. These don't directly affect SEO ranking but are a best practice that Google's security checkers flag.

Add a headers block to vercel.json with at minimum: X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: strict-origin-when-cross-origin.
